# Sentinel Security Audit Report

**Date:** 2026-07-08
**Type:** Automated Codebase Scan against `.specs/boundary-conditions.md`

## 📊 Summary
The audit completed successfully. The application properly implements CORS restrictions, CSRF protections, and secure cookie-based session handling. However, several security violations against the project's strict boundary conditions were detected and require remediation.

---

## 🚨 Findings

### 🔴 High / Critical: Password Hashing lacks Secret Fingerprint (SEC-07)
- **File:** `worker/src/auth.ts` (Lines 40-42) & `worker/src/crypto.ts` (Lines 4-24)
- **Violation:** The boundary condition `SEC-07` mandates that password hashes must use a SHA-256 fingerprint generated from Cloudflare secrets (e.g. `env.AUTH_SECRET`) to invalidate legacy sessions if a secret changes. Currently, `crypto.ts` implements a pure PBKDF2-SHA256 hash utilizing only the generated salt, entirely omitting the application secret key layer.

### 🔴 High: Domain Input Sanitization / SSRF Risk (SEC-13)
- **File:** `worker/src/index.ts` (Lines 104, 222)
- **Violation:** The boundary condition `SEC-13` dictates that domain inputs must be strictly sanitized to only allow alphanumeric characters, hyphens, and dots to prevent SSRF and Path Traversal on downstream RDAP providers. The current implementation only runs `.trim().toLowerCase()` and checks for `.includes(".")`. Malicious inputs with slashes or control characters can bypass this and manipulate `fetch()` calls in `rdap.ts`.

### 🟡 Medium: Rate Limiting is Global, not Per-IP
- **File:** `worker/src/index.ts` (Lines 57-61)
- **Violation:** The boundary condition requires login attempts to be throttled to 5 failed attempts per minute **per IP**. The current D1 query (`SELECT COUNT(*) as cnt FROM events WHERE type = 'auth' AND message LIKE 'Failed login%'`) performs a global count without IP isolation. This could allow a single attacker to lock out all authentic users from the system or bypass distributed tracking.

---

## ✅ Verified Protections
- **Token Handling (SEC-01):** Tokens are securely set as `HttpOnly; Secure` cookies and are completely absent from JSON response bodies.
- **CSRF Protection (SEC-03):** State-changing endpoints (POST/PATCH/DELETE) successfully require the `X-Requested-With: XMLHttpRequest` header.
- **CORS Constraints:** CORS middleware correctly restricts origins to `gnn.tr`, subdomains, Cloudflare pages, and `localhost` without using dangerous wildcards.
- **Reset Sequence:** Database cleanup and reset sequences properly drop state and handle cascade dependencies.
